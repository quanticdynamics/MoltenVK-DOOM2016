# DOOM (2016) on Apple Silicon — patched MoltenVK

This fork of [MoltenVK](https://github.com/KhronosGroup/MoltenVK) carries three small, game-specific hacks that let **DOOM (2016)** run on Apple Silicon Macs (M1–M4) through [NotProton](https://github.com/NotProtonNot/NotProton) and CrossOver.

> Unofficial. Not affiliated with Khronos, CodeWeavers, id Software or Bethesda. These are hacks, not conformant fixes: expect possible visual glitches. Use at your own risk.

## Why stock MoltenVK fails

DOOM (2016) has no DirectX renderer, only OpenGL 4.5 and Vulkan. macOS stops at OpenGL 4.1, so D3DMetal can't help and the only route is **Vulkan → MoltenVK → Metal**. On that route the game crashes silently at startup, for three reasons:

| # | Error in the logs | Cause |
|---|---|---|
| 1 | `vkCreateDevice failed (VK_ERROR_FEATURE_NOT_PRESENT)`, "15th flag" | id Tech 6 requires `depthBounds`. Upstream MoltenVK only exposes it on Apple10-class GPUs (M5). |
| 2 | Same error, "39th flag" | id Tech 6 requires `shaderCullDistance`, which upstream MoltenVK doesn't expose. |
| 3 | `Render pipeline compile failed: Vertex attribute in_TexCoord1(4) is missing from the vertex descriptor` | Some vertex shaders read an input the game never supplies. PC Vulkan drivers tolerate this; Metal refuses to build the pipeline. |

## Requirements

- An Apple Silicon Mac. Tested on an M4 with 16 GB RAM.
- Steam for macOS with **NotProton** installed and working, using its **Rosetta** CrossOver runner (the build NotProton recommends).
- DOOM (2016) installed through Steam, with NotProton's CrossOver selected under DOOM → Properties → Compatibility.

Tested with CrossOver 26.3 (build 26.3.0.39832) as the NotProton runner. Other CrossOver versions may work, but haven't been tested. A regular CrossOver Steam bottle should also work in principle, but that's untested too.

## Install (prebuilt)

Run these in Terminal. Quit Steam first.

**1. Download the patched library and check its checksum.**

```sh
mkdir -p ~/Downloads/moltenvk-doom2016 && cd ~/Downloads/moltenvk-doom2016
curl -LO https://github.com/quanticdynamics/MoltenVK-DOOM2016/releases/latest/download/libMoltenVK.dylib
curl -LO https://github.com/quanticdynamics/MoltenVK-DOOM2016/releases/latest/download/libMoltenVK.dylib.sha256
shasum -a 256 -c libMoltenVK.dylib.sha256
xattr -d com.apple.quarantine libMoltenVK.dylib 2>/dev/null; true
lipo -info libMoltenVK.dylib
```

`shasum` should print `libMoltenVK.dylib: OK`, and `lipo` should list both `x86_64` and `arm64`. The `x86_64` part is the one CrossOver uses, because its Wine runs under Rosetta.

**2. Find NotProton's CrossOver runner.**

```sh
ls -d ~/Library/Application\ Support/notproton/runners/crossover-*
```

If you see more than one folder, use the one matching the CrossOver version shown in DOOM's Compatibility tab. Set `R` to that folder, adjusting the version number if yours differs:

```sh
R=~/Library/Application\ Support/notproton/runners/crossover-26.3.0.39832
find "$R" -name 'libMoltenVK*.dylib' -exec ls -l {} \;
```

**3. Back up the original and install the patched copy.**

This only touches NotProton's private copy of CrossOver, never `/Applications/CrossOver.app`.

```sh
NEW=~/Downloads/moltenvk-doom2016/libMoltenVK.dylib
find "$R" -name 'libMoltenVK*.dylib' -type f | while read -r f; do
  cp -n "$f" "$f.bak" && cp "$NEW" "$f" && codesign --force --sign - "$f" && echo "patched: $f"
done
```

- `-type f` skips symlinks, so only real library files are replaced.
- `cp -n` never overwrites an existing `.bak`, so your original stays safe if you run this again.
- `codesign --sign -` ad-hoc signs the new file so macOS will load it.

## Launch the game

In Steam, set DOOM → Properties → General → Launch Options to:

```
%command% +r_renderAPI 1 +com_skipIntroVideo 1
```

`+r_renderAPI 1` forces Vulkan, the only renderer that can work on a Mac. `+com_skipIntroVideo 1` skips the intro video. If you get a black screen in fullscreen, add `+r_fullscreen 0` to try windowed mode.

The first launch can sit on a black screen for a while as shaders are translated to Metal. Later launches are faster.

## Check that it worked

After launching once, run:

```sh
W=~/Library/Application\ Support/notproton/launchers/379720/notproton-wine.log
grep -m1 'MoltenVK version' "$W"
grep -E 'HACK:|mvk-error' "$W" | cut -c1-200 | sort | uniq -c | sort -rn | head
```

You should see `MoltenVK version 1.4.3` (stock CrossOver reports `1.2.10`), a few `HACK: vertex attribute in_TexCoord1(4) ... borrowing Metal vertex buffer` lines, and no `FEATURE_NOT_PRESENT` or `Render pipeline compile failed` errors.

## Uninstall

Restore the originals from the backups:

```sh
R=~/Library/Application\ Support/notproton/runners/crossover-26.3.0.39832
find "$R" -name 'libMoltenVK*.dylib.bak' | while read -r b; do mv "$b" "${b%.bak}"; done
```

A NotProton or CrossOver update that redeploys the runner will also put the stock MoltenVK back. If DOOM starts crashing again after an update, repeat steps 2 and 3.

## Build from source instead

You don't need Xcode for this. The Command Line Tools and CMake are enough.

```sh
xcode-select --install            # if you don't have the Command Line Tools yet
brew install cmake
git clone https://github.com/quanticdynamics/MoltenVK-DOOM2016.git
cd MoltenVK-DOOM2016
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES="x86_64;arm64"
cmake --build build -j"$(sysctl -n hw.ncpu)"
lipo -info build/MoltenVK/libMoltenVK.dylib
```

The first configure step downloads the dependencies, so it takes a while. Then run the install step above with `NEW="$PWD/build/MoltenVK/libMoltenVK.dylib"`; `cp` follows the symlink to the real file.

## Troubleshooting

All paths are under `~/Library/Application Support/`.

| Symptom | What to check |
|---|---|
| `MoltenVK version 1.2.10` in the log | The patched file isn't being loaded. Check you replaced the files in the runner folder that matches your selected CrossOver version. |
| DOOM shows "not installed" when Steam is started from Terminal | Expected. NotProton only patches Steam when it's launched normally from Applications. |
| A new `mvk-error` "Nth flag" error | The game needs another Vulkan feature. Please open an issue with the log line. |
| Crash after loading | Look in `Steam/steamapps/compatdata/379720/pfx/drive_c/users/steamuser/Saved Games/id Software/DOOM/base/` for `ErrorLog_*.txt` or `Crash.*.html`, and attach them to an issue along with `notproton/launchers/379720/notproton-wine.log`. |

## What the patch changes

All three changes are in [one commit](https://github.com/quanticdynamics/MoltenVK-DOOM2016/commit/b0205c69), and each is marked `DOOM2016 HACK` or `LOCAL HACK` in the source:

1. `MVKDevice.mm`: `VkPhysicalDeviceFeatures::depthBounds` is always reported as supported. On GPUs without hardware depth bounds, MoltenVK's command encoder already skips the test, so the game renders without it.
2. `MVKDevice.mm`: `shaderCullDistance` is reported as supported. SPIRV-Cross can already emit cull distance for MSL.
3. `MVKPipeline.mm`: after the vertex function is compiled, any vertex attribute the shader reads but the pipeline leaves undefined is pointed at offset 0 of a vertex buffer the pipeline already binds. The read is valid memory and the shader gets meaningless values, which is what Vulkan allows for an unbound input. A similar hack by squidbus is used in [MoltenVK-Detroit](https://github.com/DiAvisoo/MoltenVK-Detroit).

Base: upstream MoltenVK `5189f8de`, version 1.4.3. Its code is identical to `67b26826` (October 8, 2026), the build that was tested; later upstream commits only changed docs.
