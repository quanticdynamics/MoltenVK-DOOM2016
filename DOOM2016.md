# Play DOOM (2016) on an Apple Silicon Mac

This is a small fix that lets **DOOM (2016)** run on Macs with Apple Silicon (M1, M2, M3 or M4) through Steam, using [NotProton](https://github.com/NotProtonNot/NotProton) and CrossOver.

Without it, the game crashes silently straight after you press Play.

> **Unofficial.** Not made by or affiliated with id Software, Bethesda, CodeWeavers or Khronos. It's a workaround, so you may see the odd visual glitch. Use at your own risk.

- **[Easy install (for everyone)](#easy-install-for-everyone)**: about 2 minutes, with one copy-and-paste.
- [Developer guide](#developer-guide): manual install, building from source, and what the patch changes.

---

## Easy install (for everyone)

### Before you start

You need all of these already working:

- ✅ A Mac with **Apple Silicon** (M1 or newer). To check: Apple menu  → **About This Mac**, and look for "Chip: Apple M…".
- ✅ **Steam** with **NotProton** installed and set up.
- ✅ **DOOM** installed in Steam, with NotProton's **CrossOver** selected for it: right-click DOOM → **Properties** → **Compatibility**.
- ✅ You've pressed **Play** at least once. It's fine if it crashed; that's what this fixes.

### Step 1: Quit Steam

Click **Steam** in the menu bar, then **Quit Steam**. Closing the window isn't enough.

### Step 2: Open Terminal

Press **⌘ Command + Space**, type **Terminal**, and press **Return**.

### Step 3: Paste this and press Return

```
curl -fsSL https://raw.githubusercontent.com/quanticdynamics/MoltenVK-DOOM2016/main/install-doom2016.sh | bash
```

It downloads the fix, checks the download isn't damaged, backs up the original file and installs the new one. You should finish with green ✓ ticks and **Done!**. You can close Terminal after that.

### Step 4: Set DOOM's launch options

1. Open Steam again.
2. Right-click **DOOM** → **Properties** → **General**.
3. In **Launch Options**, paste:

   ```
   %command% +r_renderAPI 1 +com_skipIntroVideo 1
   ```

### Step 5: Play

Press **Play**. **The first launch can show a black screen for a few minutes** while the game prepares its graphics. Leave it running. Later launches are much faster.

### Good to know

- **If DOOM starts crashing again after a NotProton or CrossOver update**, the update probably removed the fix. Repeat Steps 1–3.
- **To remove the fix**, quit Steam and paste this into Terminal:
  ```
  curl -fsSL https://raw.githubusercontent.com/quanticdynamics/MoltenVK-DOOM2016/main/install-doom2016.sh | bash -s -- --uninstall
  ```
- The fix only changes NotProton's own private copy of CrossOver. Your CrossOver app and your other games aren't touched.

### Something went wrong?

| What you see | What to do |
|---|---|
| "Steam is running" | Quit Steam fully (Step 1), then run Step 3 again. |
| "NotProton's CrossOver runner wasn't found" | NotProton isn't set up yet. Install it and launch DOOM with it once first. |
| "This patch is for Apple Silicon Macs" | Your Mac has an Intel chip, and this fix doesn't apply to it. |
| Black screen for more than about 10 minutes | Quit DOOM, add `+r_fullscreen 0` to the end of the Launch Options (windowed mode) and try again. |
| DOOM shows "not installed" | Open Steam from your **Applications** folder or the Dock, not from Terminal. |
| Still crashing | [Open an issue](https://github.com/quanticdynamics/MoltenVK-DOOM2016/issues) and say which Mac you have. The [developer guide](#troubleshooting) shows which log files to attach. |

## Developer guide

### Why stock MoltenVK fails

DOOM (2016) has no DirectX renderer, only OpenGL 4.5 and Vulkan. macOS stops at OpenGL 4.1 and D3DMetal only translates DirectX, so the only route is **Vulkan → MoltenVK → Metal**. On that route it fails three times in a row:

| # | Error in `notproton-wine.log` | Cause |
|---|---|---|
| 1 | `vkCreateDevice ... VK_ERROR_FEATURE_NOT_PRESENT`, "15th flag" | id Tech 6 requires `depthBounds`. Upstream MoltenVK only exposes it on Apple10-class GPUs. |
| 2 | Same error, "39th flag" | id Tech 6 requires `shaderCullDistance`, which upstream doesn't expose. CrossOver's bundled MoltenVK 1.2.10 does. |
| 3 | `Render pipeline compile failed: Vertex attribute in_TexCoord1(4) is missing from the vertex descriptor` | Some vertex shaders read an input the pipeline never supplies. Vulkan drivers tolerate it; Metal refuses to build the pipeline, and the engine throws a C++ exception. |

### What the patch changes

All of it is in [one commit](https://github.com/quanticdynamics/MoltenVK-DOOM2016/commit/b0205c69), marked `DOOM2016 HACK` or `LOCAL HACK` in the source:

1. **`MVKDevice.mm`**: `VkPhysicalDeviceFeatures::depthBounds` is always reported. On GPUs without hardware support, the command encoder already skips the test.
2. **`MVKDevice.mm`**: `shaderCullDistance` is reported. SPIRV-Cross already emits cull distance for MSL.
3. **`MVKPipeline.mm`**: after the vertex function is compiled, every active Metal vertex attribute with no descriptor is pointed at offset 0 of a vertex buffer the pipeline already binds. The format is chosen to match the shader type: `Char4`, `UChar4` or `UChar4Normalized`. The fetch is valid memory and the values are meaningless, which matches Vulkan's "undefined" semantics. A similar hack by squidbus is used in [MoltenVK-Detroit](https://github.com/DiAvisoo/MoltenVK-Detroit).

Base: upstream MoltenVK `5189f8de`, version 1.4.3. Its code is identical to `67b26826` (October 8, 2026), the build that was tested; later upstream commits only changed docs.

Tested on an M4 with 16 GB RAM, using NotProton's Rosetta runner on CrossOver 26.3 (`26.3.0.39832`).

### Manual install

The [installer script](install-doom2016.sh) does exactly this:

```sh
# Quit Steam first
cd "$(mktemp -d)"
curl -LO https://github.com/quanticdynamics/MoltenVK-DOOM2016/releases/latest/download/libMoltenVK.dylib
curl -LO https://github.com/quanticdynamics/MoltenVK-DOOM2016/releases/latest/download/libMoltenVK.dylib.sha256
shasum -a 256 -c libMoltenVK.dylib.sha256
lipo -info libMoltenVK.dylib                    # must list x86_64 and arm64 (CrossOver's Wine runs under Rosetta)
xattr -d com.apple.quarantine libMoltenVK.dylib 2>/dev/null

R=~/Library/Application\ Support/notproton/runners    # all runners; narrow to one crossover-* folder if you prefer
find "$R" -name 'libMoltenVK*.dylib' -type f | while read -r f; do
  cp -n "$f" "$f.bak" && cp libMoltenVK.dylib "$f" && codesign --force --sign - "$f" && echo "patched: $f"
done
```

- `-type f` skips symlinks.
- `cp -n` keeps the first backup safe if you re-run this.
- An ad-hoc signature is enough for CrossOver to load the library.

To restore the originals:

```sh
find ~/Library/Application\ Support/notproton/runners -name 'libMoltenVK*.dylib.bak' |
  while read -r b; do mv "$b" "${b%.bak}"; done
```

### Verify

```sh
W=~/Library/Application\ Support/notproton/launchers/379720/notproton-wine.log
grep -m1 'MoltenVK version' "$W"                 # expect 1.4.3 (stock CrossOver: 1.2.10)
grep -E 'HACK:|mvk-error' "$W" | cut -c1-200 | sort | uniq -c | sort -rn | head
```

You should see `HACK: vertex attribute in_TexCoord1(4) ... borrowing Metal vertex buffer N`, and no `FEATURE_NOT_PRESENT` or `Render pipeline compile failed` lines.

### Build from source

You don't need Xcode. The Command Line Tools and CMake are enough:

```sh
xcode-select --install          # if needed
brew install cmake
git clone https://github.com/quanticdynamics/MoltenVK-DOOM2016.git && cd MoltenVK-DOOM2016
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES="x86_64;arm64"
cmake --build build -j"$(sysctl -n hw.ncpu)"
lipo -info build/MoltenVK/libMoltenVK.dylib
```

Then install `build/MoltenVK/libMoltenVK.dylib` as in [Manual install](#manual-install). Releases are built the same way by [`.github/workflows/doom2016-release.yml`](.github/workflows/doom2016-release.yml), with a deployment target of macOS 12.0.

### Troubleshooting

All paths are under `~/Library/Application Support/`:

| Symptom | Check |
|---|---|
| Log still says `MoltenVK version 1.2.10` | The patched file isn't being loaded. Make sure you patched the runner folder that matches the CrossOver version selected in DOOM's Compatibility tab. |
| New `FEATURE_NOT_PRESENT` "Nth flag" error | Another `VkPhysicalDeviceFeatures` member is missing, counted from 1. Please open an issue with the log line. |
| Crash after loading | Attach `Steam/steamapps/compatdata/379720/pfx/drive_c/users/steamuser/Saved Games/id Software/DOOM/base/ErrorLog_*.txt` or `Crash.*.html`, plus `notproton/launchers/379720/notproton-wine.log`, to an issue. |
| "Not installed" when Steam is started from Terminal | Expected: NotProton injects itself only when Steam is launched normally. |
